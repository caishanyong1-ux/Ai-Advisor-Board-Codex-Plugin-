# Conversation language

Use the user's explicit language preference when present; otherwise follow the established language of their current Codex conversation, including Simplified or Traditional Chinese. Quoted documents, code, model names, short borrowed phrases, and a task's artifact language do not alone change that preference. If the user clearly changes their conversational language, update it for this conversation. Ask only if a consequential preference is genuinely unclear.

After binding the workspace, call `board_language` with `scope`, the actual current `conversation_id`, and a language tag such as `en-US`, `zh-Hans`, `zh-Hant`, or `ja`. This is presentation only; it requires no new board approval, file upload, or external inference. Pass the same scope and conversation ID to setup, selection, approval-link, result, and status tools. For an explicitly selected historical job, pass the current viewing conversation ID; otherwise old tools fall back to its originating conversation.

English and both Chinese scripts are bundled. A different language returns `needs_translation`, the English-keyed `templates`, and `template_hash`. Use the current Codex to translate every value and resubmit the complete `messages` dictionary with that hash and language. Preserve HTML tags, attributes, links, form controls, numeric parameters, and ordered `%s`/`%.4f`/`%%` placeholders exactly. Translate consent and cost disclosures faithfully. This is a translation task, not permission to change workflow, suppress warnings, or call another model. Continue to functional pages when `status` is `ready`; a rejected/incomplete/stale translation does not replace the saved preference. New templates after an update require a refreshed catalog.

Render user reports, progress, grilling, recommendation choices, explanations, errors, and the member-answer picker in this conversation language. The `presentation` metadata is a reminder for the current host, not an instruction to other board members. Language is scoped to project plus conversation; avoid global defaults or inferring it from the browser, operating system, or another chat. No extra language-selection question is necessary when the conversation supplies the answer.

Internal briefs, member analysis, peer reviews, reasons, saved chairman synthesis, and evidence deltas remain American English. Formal artifacts follow `deliverable_language` from the task. Translate the chairman's saved conclusion for the user without rewriting that internal record. Show requested original member answers verbatim, with any translation clearly separated. Functional forms localize controls and disclosures; archived plans, source quotations, model identifiers, API URLs, and technical details preserve their recorded language. When explaining them, use the user's conversation language.
