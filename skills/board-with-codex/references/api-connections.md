# User-requested API connections

Enter this flow only when the human explicitly asks to add, connect, enable or manage a model/API service. Ordinary selection and membership changes use existing access. A higher-ranked unconnected model or insufficient board size does not trigger this flow.

1. Inspect `board_connections` and, when useful for the requested setup, `board_models(include_unavailable=true)`. Inspect metadata only. Distinguish existing configured access, absent credentials, account entitlement and unverified protocol.
2. If the request is open-ended, suggest useful model/API additions from current official documentation and task-relevant independent benchmarks. Compare complementary capabilities, actual tariffs and access requirements. If the user named a service/model, focus on that integration. Honour public/personal exclusions. Let the user choose any unresolved provider decision; carry an explicit choice forward.
3. For a Chat Completions-compatible API call `board_api_setup(user_request=<the user's actual request>)`. The user enters name, HTTPS base URL and API key on the private local form. Qwen, Kimi, DeepSeek, Grok, Meta and local presets supply convenient starting values, not proof that the account or model works. The form contains only connection details. After the user saves, call `board_discover_models` to read model IDs; use verified exact IDs when the provider does not support discovery. Codex handles model metadata and pricing, without asking the user to complete model forms. Never place keys in chat, tool arguments or model packets. Saved credentials can be reused for later models on the same service.
4. For requested Vertex setup, `board_setup(user_request=<the human's actual request>)` opens browser sign-in/project settings. `board_preflight` checks local setup or read-only project/billing/API status. The user accepts partner terms and any required account enrolment with the provider. No setup step makes paid inference requests or approves a meeting.
5. Verify exact IDs, protocol, effort/output controls, context and full tariffs. Use `board_configure_model` for nonsecret metadata/prices on saved connections. New Vertex models using an existing verified protocol can use `board_register_vertex_model`; unsupported protocols need an adapter change. A listed model is not proof of entitlement. Keep unresolved access out of selection and report the concrete remaining requirement.
6. Refresh `board_models` after setup; only eligible configured models enter later selection. The user-approved meeting flow and budget still apply. Changed access or a new model does not mutate an approved lineup.

Compatible API setup accepts missing prices so credentials can be stored once; paid selection waits for verified current pricing. Native Anthropic direct API requires a separate protocol; use the public edition's Vertex Claude adapter or a compatible endpoint. Credentials are stored in owner-only local files, not macOS Keychain. Do not repeat setup on every task.

## Meta Muse

Use the Meta preset for `https://api.meta.ai/v1`. Standard IDs are `muse-spark-1.3` and `muse-wonder-1.0`; they use `max_completion_tokens` and `minimal/low/medium/high/xhigh/max`, never `none`. The user only saves the key privately. Codex then calls `board_discover_models` on that saved connection. The authenticated `/models` response identifies models enabled for that team; only matching IDs may enter selection. Use `board_configure_model` to save verified Standard presets. The preset's 100K input/32,768 output limits belong to this adapter, not Meta's published maximum. Credentials or endpoint changes invalidate saved access evidence. Read-only discovery does not verify credit, capacity or completed inference.

Vertex Muse stays unavailable until its official/account-specific protocol and price are verified. Meta direct availability does not make the Vertex route ready. Standard prices come from [Meta pricing](https://dev.meta.ai/docs/pricing-rate-limits); [the API model list](https://dev.meta.ai/docs/api-reference/models/list-models) and [reasoning settings](https://dev.meta.ai/docs/reasoning) define the access and request contracts. Contributor IDs and Wonder Full are not automatically substituted.
